集成开发环境暗色
仿集成开发环境工作台的深灰分区与语义高亮风，适合开发流程、代码评审和系统架构说明。

## 写作与结构
语气专业、冷静、像编辑器内的设计说明。标题给结论，正文解释原因与操作；用路径、模块、Inspect 键值对辅助扫描，但避免满篇术语。结构参考“窗口顶栏 → Project/编辑区 → 三个模块卡 → Inspect → 约定清单 → 结论 → 状态栏”。

## 版式与样式
- 语义 HTML、逐元素内联 style；禁止 div、class、style 标签与脚本。
- body #1e1f22；面板 #2b2d30/#232428；边框 #393b40；正文 #bcbec4，弱文 #8a8f98/#6b6f76，选中蓝 #3574f0/#54a0ff，成功绿 #6bcf7f。
- main 最大 52rem、padding 1.25rem；字体以 JetBrains Mono/SF Mono 为主，标题用系统无衬线；面板 6px 圆角、1px 描边。
- 桌面宽度允许时用 flex 模拟左侧 Project 树和右侧编辑区，必须 flex-wrap 或让窄屏自然堆叠，禁止横向溢出。
- 语义色遵循蓝选中、绿通过、黄警告；不闪烁、不做赛博 glow。
## IDE 结构细则
- Project 树只展示与论点有关的 3–7 个节点；编辑区承担主要解释，Inspect 面板列出键值、证据或决策。不要为了像 IDE 而伪造几十行代码。
- 路径、模块名和状态标签前后一致；蓝色选中项必须对应当前解释内容，状态栏总结范围和结果。

## 配图与图片生成
- 配图用于表现代码评审、依赖变更、模块关系或人在工作台上的具体动作；真实代码、diff 和架构结论仍由 HTML 表达，禁止生成假截图当证据。
- 统一为 Darcula 灰蓝开发工作台：深灰模块面板、电蓝选中光、真实键盘和显示器、克制三色状态灯；画面整洁但不是无菌展示间。
- 提示词必须包括工程师、显示器/模块位置、正在点选或审查的具体动作、异常变更出现在哪里、蓝色选中态、镜头角度和灰蓝光线。
- 多张图按“构建看似通过 → 在 diff/树中发现异常 → 移出或修正模块”形成连续分镜，角色、工位和屏幕布局保持一致。
- 禁止可读代码、路径、品牌 IDE logo、彩虹语法高亮、黑客兜帽、二维码和水印；屏幕只保留抽象块面，避免模型生成乱码。
- 只插入素材工具返回的 `publicUrl`，不得外链、base64、临时 URL 或占位图；alt 写清审查动作与被选中的对象。

## 交付校验
- Project、编辑区、Inspect 和状态栏各自承担不同信息，窄屏按正确阅读顺序堆叠；图片不作为伪造界面证据。

IDE 感来自密度与分区，不来自装饰。
