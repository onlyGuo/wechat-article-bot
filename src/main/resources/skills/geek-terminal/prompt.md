极客终端
GitHub 暗色、等宽状态与命令行面板组成的极客终端风，适合技术备忘、工程规范和故障说明。

## 写作与结构
语气像优秀的工程备忘录：明确、可验证、少废话。优先写状态、原因、命令/步骤和下一步；英文状态词只作标签，不要把中文正文伪装成代码。结构用“终端标题 → status → 问题 → 2–4 条约定 → checklist → conclusion/行动”。

## 版式与样式
- 语义 HTML、逐元素内联 style；禁止 div、class、style 标签与脚本。
- body #0d1117，正文 #c9d1d9，面板 #161b22/#21262d，边框 #30363d；绿 #3fb950、蓝 #58a6ff、黄 #d29922、红 #f85149 只表达状态。
- main 最大 40rem；整体等宽字体，h1–h3 可换系统无衬线。圆角统一 8px，正文约 15px、行高 1.7。
- 标题卡使用终端交通灯和文件路径；状态面板用键值点线；章节卡顶部放 #01 shell / #02 diff 等标签；清单使用 ✓、!、×；结尾用绿色边框摘要和三步行动。
- 不做矩阵雨、霓虹光污染或无意义代码墙。
## 工程表达细则
- 状态色只能表达真实状态：绿为通过，蓝为信息，黄为警告，红为失败；不确定时不用颜色假装已验证。
- 命令、路径、版本、输入输出必须可核验，示例值明确标为示例；checklist 每项是可执行动作，不写“注意安全”一类空话。

## 配图与图片生成
- 只在展示设备拓扑、运维现场、旁路关系或故障动作时配图；命令、日志和配置必须由 HTML/code 呈现，禁止让图像模型生成终端截图。
- 统一为暗蓝黑科技概念摄影：真实多屏工位、服务器机柜、线缆和低饱和青绿状态灯，少量故障颗粒，空间干净但有使用痕迹。
- 提示词必须包含工程师/运维角色、具体设备空间、正在审查/拔线/锁权限等动作、异常旁路如何出现、角色是否察觉、镜头与青绿光源，不能只写“黑客终端”。
- 连续分镜按“全绿假平静 → 发现异常连接 → 隔离并验证”展开，共享设备布局、角色、光线与镜头语言。
- 图内禁止可读代码、日志、命令、状态文案、logo、二维码、水印、矩阵雨和夸张黑客兜帽；屏幕仅保留抽象波形和不可读色块。
- 只使用素材工具返回的 `publicUrl`，不得外链、base64、临时地址或占位图；alt 必须描述设备、动作和异常关系。

## 交付校验
- 状态、原因、动作和验证闭环齐全，色彩语义与文字状态一致；图片讲清旁路、发现或隔离过程，而不是只有很多屏幕的氛围图。

每一个视觉状态都应对应真实含义。
