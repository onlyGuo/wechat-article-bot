01 · 问题在哪

工具越多，手越生。快捷键记了三层，真正交付时仍在页面里点来点去。

极客风格不是「炫」，是把复杂度压回可观察的状态：有提示符、有状态、有下一步。

readable > clever · explicit > magic · one file when possible

02 · 三条工作约定

#01 shell

先写命令，再写包装

能一条命令做完的事，不要先开一个项目。终端是第一界面。

#02 diff

改动必须可回看

提交信息写「为什么」，不写「改了一下」。未来只读 diff 的人包括你自己。

#03 log

状态要能被打印

系统出问题时，先保证你能看见发生了什么，而不是先猜。

notes/checklist.sh

! 避免：无意义缩写、先包装后实现

// conclusion

工具要服务手，而不是绑架手

页面可以极客，过程必须无聊：结构固定、颜色克制、状态可见。

ship small · keep logs · delete what you do not need
