幻灯片叙事
深靛蓝、一屏一结论和大字少句组成的演示稿风，适合提案、方法论与高层摘要。

## 写作与结构
每一屏只讲一个判断。标题就是结论，正文最多 1–3 句或 3 个要点；语言适合口头讲述，有停顿，不把报告全文塞进页面。顺序参考“封面 → 议程/问题 → 方法 → 行动 → 收束”，简单主题可删减页面。

## 版式与样式
- 每个主要 section 近似一页；语义 HTML、逐元素内联 style，禁止 div、class、style 标签与脚本。
- body #0f1220；面板 #151a30，边框 #2a3358，强调靛蓝 #7c8cff，主字 #fff，次字 #a8b0d4。
- main 最大 48rem；页面 min-height 40–70vh、padding 2.25rem、16px 圆角。主标题 clamp(2.2rem,6vw,3.4rem)，页标题 1.8–2.4rem。
- 每页含小号等宽页码标签、大标题和一个主要信息面；允许少量芯片、列表或径向渐变，不堆多组卡片。
- 页脚用圆点显示进度；避免动画、轮播和文档式长段落。
## 演示节奏细则
- 每屏标题在脱离正文时仍是一句完整结论；副文解释“为什么”，要点解释“怎么办”，不能三者重复。
- 议程只列真正会讲的内容，方法页给步骤或关系，行动页给责任与下一步；页码和进度点与实际屏数一致。

## 配图与图片生成
- 配图仅在一张概念分镜能比文字更快解释冲突、机制或未来状态时使用；数字、流程和对比优先用 HTML/SVG，不能让图片模型画 PPT。
- 统一为 Keynote 概念视觉：深靛蓝舞台、单一人物/物体剪影、克制聚光、少量粒子和巨大负空间；画面必须适合在一屏内远距离识别。
- 提示词写清主体、舞台/投影空间、正在做的动作、需要表达的关系、镜头、聚光方向、靛蓝层次和标题留白，不能只写“高端发布会”。
- 多图对应“问题 → 方法 → 行动”三个关键页，并保持同一主体、舞台、光源和透视；每一张换一个信息动作而非只换颜色。
- 禁止在投影、屏幕或画面中生成标题、要点、数据、logo、二维码、水印和真实品牌发布会；所有可读内容由 HTML 排版。
- 只使用素材工具返回的 `publicUrl`，不得外链、base64、临时 URL 或占位图；alt 描述主体动作和概念关系。

## 交付校验
- 一次滚动得到一个结论，单屏文字不过载，移动端按页保持清楚层级；图片可以远看识别且不复读标题。

读者滚动一次，就应得到一个完整结论。
